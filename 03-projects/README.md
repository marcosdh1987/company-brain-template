# 03-projects

One folder per project or initiative. Copy `_project-template/` to start one.
Project folders hold the project's **canonical** documents; their evidence
still lands in `01-meetings/`, `09-references/`, or `99-inbox/` and gets
promoted here.

The proven shape (from real engagements):

```text
<project>/
├── overview.md         # objective, scope, out-of-scope/BLOCKED, canonical sources
├── current-state.md    # what exists today (observed, cited)
├── target-state.md     # where it should land (approved, not aspirational)
├── plan.md             # how to get there, step by step
├── checklist.md        # execution tracking
├── open-questions.md   # project-scoped Q-<PROJ>-XXX (rolled up in 05-requirements)
└── change-log.md       # dated log of state changes and superseded facts
```

Keep **current state / target state / recommendation / decision** separate in
every document — blurring them is the #1 source of false confidence.
